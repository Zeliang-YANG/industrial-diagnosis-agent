# DeepSeek 真实联调结果

日期：2026-09-07。模型：deepseek-v4-flash。数据库：yzl_agent_demo（模拟数据）。

## 已验证

- API Key 可用，后端能够完成真实模型请求。
- 模型自动选择 query_kpi、query_fault_events、query_device_state 三个只读工具。
- 工具参数校验后查询本机 MySQL，结果通过 tool_call_id 正确回传模型。
- 首次成功回答的 KPI 数值与工具输出舍入后相符，并引用了故障事件 status_event_log:111。
- 模型区分模拟故障字典与已确认物理根因。
- 标记数据质量后，第二次成功回答明确指出状态事件重叠，KPI 不可用作真实设备效率判断。

## 联调发现与处理

系统代理下首次 POST 失败，直连成功。DeepSeek 客户端默认直连，可用环境变量显式启用系统代理，其他应用不受影响。

演示库存在未关闭的旧事件 208，与后续事件重叠。原计算会重复累计时间，导致低 OEE。
本次未修改原始事件；增加 overlapping_state_events 警告和 data_quality=invalid 标记。
第一份回答虽数值对应工具，但对长时间待机的解释不足以作为可靠诊断，不应直接用于演示设备根因。
第二份回答正确识别了数据质量限制。事件 ID 预览截断与完整事件工具分页不同，已进一步补充提示词解释。
