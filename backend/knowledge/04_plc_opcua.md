# PLC 与 OPC UA 通信诊断手册

## 通信中断与 PLC 故障的区分

通信中断表示采集端无法获得可信数据，PLC 系统故障表示控制器可通信但报告内部异常。前者先检查网络可达性、OPC UA 会话、端点、安全策略、证书、NodeId 和服务器状态；后者应查看 PLC 诊断缓冲区、模块状态和现场总线。采集端断线期间不能根据最后一个值推断设备持续处于原状态。

## OPC UA 连接异常

按端点可达、会话建立、认证与证书、节点读取、订阅更新、时间戳六层定位。能够建立 TCP 连接不代表变量持续更新；节点可读也不代表时间戳新鲜。记录服务端时间戳、源时间戳和客户端接收时间，才能区分设备未更新、网络延迟和客户端处理阻塞。

## NodeId 或变量映射异常

新增设备或程序版本变化后，先核对命名空间索引、NodeId、数据类型、工程单位和刷新频率。若值始终为默认值，检查节点映射和访问权限；若值偶发跳变，检查类型转换、字节序、量程和无效值处理。不要通过猜测节点含义修复生产映射。

## 多设备同步异常

多个设备同时离线时，优先检查共享网络、交换机、OPC UA 服务端和采集进程。只有单台设备异常时，再下钻到该设备连接与控制器。状态时间线需要使用统一时钟；时钟偏差会制造虚假的先后关系。

## 恢复后的验证

恢复后检查会话稳定性、数据更新时间、事件是否正确闭合，以及是否产生计数器跳变或重复事件。短暂恢复不等于问题消失，应观察一段完整生产周期并比较中断前后的更新间隔。
